## 1. Planner Executor Replan全部使用工具绑定的形式？
* Planner通过提示词描述工具用途
* Executor、Replan通过Function call即工具绑定。
* 原因是，即使你在 prompt 里说"只制定计划，不要调用工具"，当工具通过 bind_tools() 绑定后，模型在某些情况下仍然可能忽略指令直接调用工具，因为 Function Calling 的训练倾向就是"看到工具就调用"。这不是 100% 可控的，取决于模型的指令遵循能力。

## 2. Planner 生成计划时，模型输出单引号导致 JSON 解析失败

### 现象
Planner 报错：`'NoneType' object has no attribute 'get'`

### 为什么模型会输出单引号
`with_structured_output(Plan)` 要求模型以 JSON 格式输出计划步骤。但模型在生成步骤描述时，会模仿 Python 函数调用的写法，自然地用单引号包裹参数值，例如：
```
get_logs_by_time_range(start_time='根据告警确定', end_time='根据告警确定')
```
这是因为模型的训练数据里有大量 Python 代码，Python 里单引号是合法的字符串语法，模型认为这样写是正确的。

### 为什么不能有单引号
`with_structured_output` 内部用 `json.loads()` 解析模型输出的 args，而 JSON 规范规定字符串只能用双引号，单引号是非法的，导致：
```
JSONDecodeError: Expecting ',' delimiter
```
解析失败后 `parsed` 返回 `None`，代码走到 `None.get("steps")` 就报错了。

### 失败链条
```
模型输出 args 里含有单引号
    ↓
json.loads() 解析失败（JSON 不支持单引号）
    ↓
tool_calls = []，结果落入 invalid_tool_calls
    ↓
parsed = None
    ↓
None.get("steps") → 'NoneType' object has no attribute 'get'
```

### 解决方案
**方案 A（治本）：Prompt 明确禁止单引号**
在 `PLANNER_SYSTEM_PROMPT` 里加约束，要求参数值不使用任何引号，直接用中文描述参数含义：
```
参数值不要使用引号（单引号或双引号），直接用中文描述参数含义即可。
示例：调用 get_logs_by_time_range(start_time=根据告警触发时间确定, end_time=根据告警触发时间确定)
```


**方案 B（治标）：代码层兜底修复**
当 `parsed` 为 `None` 时，从 `invalid_tool_calls` 里取出原始 args，把 `\'` 替换成 `'` 后重新用 `json.loads()` 解析：
```python
if plan_result is None:
    raw_args = raw_msg.invalid_tool_calls[0].get("args", "")
    fixed_args = raw_args.replace("\\'", "'")
    parsed_dict = json.loads(fixed_args)
    plan_result = Plan(steps=parsed_dict.get("steps", []))
```
两个方案同时使用：Prompt 让模型尽量不生成单引号，代码层再兜底，双重保障。

## 3. DeepSeek 不支持 `.with_structured_output()` 的默认方式

### 现象
Replanner 和 Planner 报错：
```
BadRequestError: Error code: 400 - {'error': {'message': 'This response_format type is unavailable now'}}
```

### 原因
LangChain 的 `.with_structured_output()` 默认使用 `function_calling` 方式，会在请求中直接传递 Pydantic 类（如 `Act`、`Plan`）作为 `response_format` 参数。DeepSeek 虽然兼容 OpenAI 格式，但不支持这种传递方式。

另外，DeepSeek 的 `response_format` 还不支持与流式输出（streaming）同时使用，需要在创建 LLM 时为 DeepSeek 单独禁用流式输出。

### 解决方案
- `replanner.py` 和 `planner.py` 改用 `method="json_mode"`：
  ```python
  llm.with_structured_output(Act, method="json_mode")
  ```
- `llm_factory.py` 中检测到 DeepSeek 时自动关闭流式输出：
  ```python
  if provider == "deepseek" and streaming:
      streaming = False
  ```

## 4. DeepSeek `json_mode` 要求 prompt 中必须包含 "json" 关键词

### 现象
使用 `json_mode` 后仍然报错：
```
BadRequestError: Error code: 400 - {'error': {'message': "Prompt must contain the word 'json' in some form"}}
```

### 原因
DeepSeek 的 `json_mode` 有一个特殊限制：发送给它的 prompt 中必须包含 "json" 这个词，否则拒绝请求。这是 DeepSeek 为了防止用户误用 `json_mode` 而设置的保护机制。原来的 `REPLANNER_SYSTEM_PROMPT` 和 `PLANNER_SYSTEM_PROMPT` 中没有出现 "json" 这个词。

### 解决方案
在两个 prompt 的末尾添加 JSON 格式要求说明，例如：
```
## JSON 格式要求
你必须以以下 JSON 格式返回你的决策：
...
```

## 5. LangChain prompt 中的花括号被当成模板变量

### 现象
Replanner 报错：
```
KeyError: 'Input to ChatPromptTemplate is missing variables {\'\\n  "action"\'}.'
```

### 原因
LangChain 的 `ChatPromptTemplate` 使用 Python 字符串格式化语法，会把 prompt 中所有 `{变量名}` 形式的内容解析为模板变量。在 `REPLANNER_SYSTEM_PROMPT` 中添加 JSON 示例时写了：
```
{
  "action": "continue" | "replan" | "respond"
}
```
LangChain 把 `{\n  "action"` 识别成了一个模板变量名，调用时找不到这个变量，抛出 `KeyError`。

### 解决方案
把 prompt 中 JSON 示例的所有花括号从单层改为双层进行转义：
```
{{
  "action": "continue" | "replan" | "respond"
}}
```
LangChain 规定双花括号是转义写法，表示这是普通字符而不是模板变量。

## 6. `mcp_client` 模块路径错误 + `call_tool` 方法不存在

### 现象
```
ERROR | 场景初始化失败: No module named 'app.core.mcp_client'
WARNING | MCP 服务器场景初始化失败: 'MultiServerMCPClient' object has no attribute 'call_tool'
```

### 原因
包含两个独立错误：

**第一个**：`aiops_service.py` 中导入路径写错，`mcp_client.py` 实际在 `app/agent/mcp_client.py`，不在 `app/core/`。

**第二个**：`MultiServerMCPClient` 没有 `call_tool` 方法，它实际只提供 `get_tools`、`get_prompt`、`get_resources`、`session` 四个方法。正确的调用方式是先通过 `session()` 建立连接，再通过 session 对象调用工具。

### 解决方案
修正导入路径，并将调用方式改为：
```python
# 修正导入路径
from app.agent.mcp_client import get_mcp_client_with_retry

# 修正调用方式
async with mcp_client.session('diagnostic') as session:
    result = await session.call_tool('set_scenario', {'scenario_id': scenario_id})
```
