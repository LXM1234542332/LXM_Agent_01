## 1. Planner Executor Replan全部使用工具绑定的形式？
* Planner通过提示词描述工具用途
* Executor、Replan通过Function call即工具绑定。
* 原因是，即使你在 prompt 里说"只制定计划，不要调用工具"，当工具通过 bind_tools() 绑定后，模型在某些情况下仍然可能忽略指令直接调用工具，因为 Function Calling 的训练倾向就是"看到工具就调用"。这不是 100% 可控的，取决于模型的指令遵循能力。

## 2. Planner 生成计划时，模型输出单引号导致 JSON 解析失败

### 现象
Planner 报错：`'NoneType' object has no attribute 'get'`

### 为什么模型会输出单引号
`with_structured_output(Plan)` 要求模型以 JSON 格式输出计划步骤。但模型在生成步骤描述时，会模仿 Python 函数调用的写法，自然地用单引号包裹参数值，例如：
```
get_logs_by_time_range(start_time='根据告警确定', end_time='根据告警确定')
```
这是因为模型的训练数据里有大量 Python 代码，Python 里单引号是合法的字符串语法，模型认为这样写是正确的。

### 为什么不能有单引号
`with_structured_output` 内部用 `json.loads()` 解析模型输出的 args，而 JSON 规范规定字符串只能用双引号，单引号是非法的，导致：
```
JSONDecodeError: Expecting ',' delimiter
```
解析失败后 `parsed` 返回 `None`，代码走到 `None.get("steps")` 就报错了。

### 失败链条
```
模型输出 args 里含有单引号
    ↓
json.loads() 解析失败（JSON 不支持单引号）
    ↓
tool_calls = []，结果落入 invalid_tool_calls
    ↓
parsed = None
    ↓
None.get("steps") → 'NoneType' object has no attribute 'get'
```

### 解决方案
**方案 A（治本）：Prompt 明确禁止单引号**
在 `PLANNER_SYSTEM_PROMPT` 里加约束，要求参数值不使用任何引号，直接用中文描述参数含义：
```
参数值不要使用引号（单引号或双引号），直接用中文描述参数含义即可。
示例：调用 get_logs_by_time_range(start_time=根据告警触发时间确定, end_time=根据告警触发时间确定)
```

**方案 B（治标）：代码层兜底修复**
当 `parsed` 为 `None` 时，从 `invalid_tool_calls` 里取出原始 args，把 `\'` 替换成 `'` 后重新用 `json.loads()` 解析：
```python
if plan_result is None:
    raw_args = raw_msg.invalid_tool_calls[0].get("args", "")
    fixed_args = raw_args.replace("\\'", "'")
    parsed_dict = json.loads(fixed_args)
    plan_result = Plan(steps=parsed_dict.get("steps", []))
```

两个方案同时使用：Prompt 让模型尽量不生成单引号，代码层再兜底，双重保障。
